## Fixture standard and limits

Use the existing public React standard: real production components/hooks, `renderToStaticMarkup` for static assertions, and existing `Fixture` with public ReactDOM and `act` for stateful checks. `IssueFixture` already provides repository-scoped Issues. Only loading and polling need small local compositions. Shared fixtures, dependencies and framework behavior are unchanged; no custom React simulation or private framework API is introduced.

Existing JSDOM geometry, scrolling, dialog and timer substitutes remain fixture limitations. The rail check retains its narrow ResizeObserver substitute. These checks exercise real React state/effects, DOM events, DOM focus and declared design values within Node. They do not establish browser layout, native dialog behavior, animation, real timer scheduling or end-to-end navigation. The refresh check substitutes HTTP responses with actual in-memory store data and invokes the real polling callbacks; it does not establish HTTP transport behavior. Issue93 must add meaningful coverage for its new navigation and copy obligations under the existing code-only profile.
