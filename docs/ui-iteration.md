## Choosing the change location

Change theme tokens for a shared color, type, radius or spacing decision. Colors are named by purpose, including distinct status, evidence, warning, source and navigation treatments. The size scales support the reference hierarchy; semantic aliases such as `--radius-control`, `--space-panel-padding` and `--font-size-control` express common roles. The active light palette resolves every feature alias through the neutral palette or a semantic status color; feature files must not embed a dark-only color.

Change a shared component for behavior or markup used by several real screens, and `components/primitives.css` for its shared appearance and responsive sizing. Button preserves native attributes and refs, and its loading state disables activation and exposes `aria-busy`. Badge preserves a native span and accepts the existing status class hooks. EmptyState owns the common message frame. Pagination owns the exact range and boundary controls; Issues, Requirements and the preview supply their own collection and page state. Modal preserves native dialog semantics, neutral initial focus, trapped bidirectional Tab navigation, Escape dismissal and return to its connected opener. Focus outlines are enabled by intentional Tab input through the shared focus-intent hook and styled by `theme/base.css`.

Change feature markup and the stylesheet beside it for screen-specific layout, including its media queries. Shared list frames, pagination and identifiers keep their historical issue-prefixed class names in `components/primitives.css` because Requirements also uses them. Mixed inspection rules used across cards, diagnostics and reports remain in the shared inspection stylesheets. Keep component primitives independent of backend reads. Keep workspace navigation presentation in the layout and navigation decisions in App. `useWorkbenchData` retains the existing abort signals, job-change refresh trigger, two-second metadata polling, retry behavior and previously loaded issues. `useIssueCollection` owns filter/search/sort, page resets, clamping and list scroll reset over its supplied scope. Requirements supplies the exact repository/requirement children from `requirementProgress`; Unassigned supplies repository-owned records with a null requirement ID. Resetting filters never widens ownership. Requirements retain their own selection and focus recovery when refreshed rows move across pages.

Production CSS stays centrally loaded through `styles.css`; components and feature modules never import CSS. Its import order is part of the cascade: tokens and document defaults precede shared primitives and inspection basics, followed by workspace, Issues, delivery basics, Requirements, shared inspection refinements, issue diagnostics, report refinements, shared inspection responsive overrides and Repo harness. The separate refinement files preserve later overrides without increasing specificity or adding cascade layers. In particular, the shared mobile metadata/evidence padding follows both feature definitions; report typography follows common inspection typography. Within `workspace.css`, responsive rail and content rules follow the desktop shell. The desktop issue panel reserves space for headings, filters and pagination while its rows scroll; other subviews scroll inside the frame. Review cascade winners when moving rules. Do not introduce CSS imports into compatibility entry points. Keep preview styles and fixtures behind the development gate.
