# Deterministic observations and uniform standards

The current [code-only verification profile](code-only-verification.md) uses Node assertions, API/storage integration and owned process outcomes. Playwright/browser execution is retired. Historical DOM observation revisions and their exact patches remain audit history rather than current test-authoring instructions.

Before checking equivalent functionality, inspect shared components and repository conventions. If two implementations use conflicting standards, select one reasonable uniform standard, record its rationale, and implement and check against it. Explicit naming, component structure, API and ownership conventions are valid requirements. Independent review must check consistency with the selected standard. Do not infer mandatory conventions solely from an incidental test implementation.

Observe application-generated values separately from expected fixture data. Match exact record identifiers and current states so a title, another record or historical report cannot satisfy a missing field. Verified and Unverified, or Merged and Not merged, must remain distinguishable. Scoped containment remains appropriate for prose where exact equality is not the requirement.

Choose checks proportionate to changed behavior and concrete risk. Avoid redundant same-field negatives when an exact positive already excludes the opposite state. Use separate negative/boundary scenarios for real rejection, mutation, ownership or integrity risks. Tests must fail because the required behavior is missing, rather than imports, setup or timeout errors.

Do not mechanically replace browser assertions with JSX/class/string snapshots. Node SSR and production builds provide limited code evidence and do not prove live visual or interaction behavior. Retired checks remain available through Git and historical delivery evidence.

For UI design checks, distinguish shared standards from mutable local recipes. Keep light semantic tokens, shared typography and token references, visible focus feedback, selected/active styling and complete icon license notices. Local rail/panel dimensions, spacing, radii, shadow geometry and visual transition timings may change while preserving functional layout relationships. Documentation wording and historical provenance paths are not permanent assertions. The exact 208px/document case in `tests/expanded-sidebar-width.test.ts` and the dropdown documentation case are retired; `tests/toolbar-provenance.test.ts` retains the complete Lucide ISC and Feather MIT notices, including the derived-icon list and disclaimers.

Use the existing PostCSS declaration reader and public ReactDOM fixture for these retained guarantees. Mutable-value examples and incorrect-result counterexamples distinguish valid local changes from inconsistent shared styling, malformed rail grids and ineffective reduced motion. Rail checks retain positive finite tracks, wider desktop expansion, compact responsive layout, toggle anchoring, non-intercepting decoration and reduced-motion overrides for elements and pseudo-elements. Shell checks retain avatar alignment, shrinkable content and bounded scrolling. Dropdown checks observe actual component state, selection, accessible names and identities, viewport containment, above/below anchoring and resize repositioning with obsolete anchors cleared. Fixed geometry inputs and the existing dialog, scrolling and manually driven polling-timer substitutes are limited Node evidence, not browser layout, native interaction or timing fidelity. Do not expand these fixtures into a browser or framework simulation.

Accepted tests remain frozen during ordinary feature work. A reviewed acceptance-contract revision records old/new identities and actual proofs; only owner maintenance may activate it. New permanent defect checks require a confirmed significant OR recurring project defect and worthwhile deterministic prevention that outweighs authoring, maintenance and execution cost. Minor one-off findings may use existing meaningful coverage plus repair and independent review with `needsRegression: false`. New business behavior still needs meaningful acceptance; significant harness safety changes retain targeted regressions. Record the judgment in existing plan defaults and review/coverage summaries, without another role, registry, schema or gate. Qualifying uncovered defects enter the existing tests, red proof, independent coverage review, freeze and repair cycle; this does not change project-specific acceptance obligations.
