# Agent-owned operations and website inspection

The user explicitly retired manual website operations: create, edit, delete, Start issue and Retry issue, together with the entire Current execution card and its disabled operation states. Codex conversation submission, API/CLI ownership checks, the serial queue, verification, review and GitHub publication remain operational. Navigation, filtering, issue/report/evidence viewing, Close/Escape and retrying failed reads remain available.

This is acceptance-contract maintenance issue 19 for requirement 4. It revises the existing manual-operation expectations before dependent feature issue 20 removes the UI. The revised compatibility checks pass against the current UI and its future inspection surface. They do not assert the feature is delivered. Feature 20 must independently prove absent operation controls and no browser mutations with fresh failing checks, followed by full verification and review. The owner integrates this contract only into the reserved requirement branch; whole-goal acceptance and GitHub publication precede activation on main.

## Required behavior replacements

| Retired manual expectation | Retained or replacement behavior |
| --- | --- |
| `create, reload, inspect API updates and confirmed deletion persist` | `API-created issues, API updates and deletions remain visible across reloads`: real POST with trimming/status/priority, reload, keyboard diagnostics, real PATCH and DELETE, persisted API and visible list results. Manual creation/deletion dialogs and confirmation focus are retired. |
| `whitespace-only titles are rejected accessibly without a mutation` | `invalid API titles are rejected without changing the inspected collection`: empty, whitespace and over-limit titles reject for real POST and PATCH; collection equality and visible sentinel remain. Form-specific aria-invalid and draft focus are retired with the form. |
| `an empty isolated workspace offers a working first-issue action` | `an empty isolated workspace remains inspectable and receives agent-created issues`: owned empty database, labelled empty view, pinned API creation, reload and inspection. The first-issue creation action is retired. Feature 20 adds agent guidance and absence assertions. |
| `a real server validation error preserves draft values and allows retry` | `a failed detail request allows read retry without losing the issue`: a failed GET is announced, Retry details reaches the real API, persisted content and opener focus recover. Unsaved web drafts are retired. Real validation stays covered by the API title/label checks and unchanged Node tests. |
| `pending creation blocks duplicate submission and dialog dismissal` | `pending details can be dismissed without leaking stale content`: pending GET, Escape focus restoration, opening another issue, releasing the obsolete request and retaining current details without stale content or alerts. Pending form submission and mutation locking are retired. |
| `invalid label drafts are rejected accessibly without a write` | `invalid API labels leave the inspected issue unchanged`: blank, over-limit, too-many and comma-containing labels reject for real POST and PATCH; collection equality and visible retained labels remain. CSV draft editing is retired. |
| `UI-assigned labels survive a full server restart` | `API-assigned labels survive a full server restart`: pinned API creation/normalization, visible labels, stopped process/removed lock, restarted server, reload and durable API labels. |

The existing workspace case now exercises accessible inspection dialog focus trapping, Escape/Close and opener restoration rather than creation fields. Phone CRUD setup/cleanup uses the API while title/identifier and Close controls remain in the viewport.

The workbench ownership/dependency case uses real API creation, persisted context, cyclic-dependency rejection and API cleanup. Both real automatic queue cases assert the stored report's `merged` outcome instead of a disabled Automatically merged button. The diagnostic admission case starts/retries through the API, asserts one queued job and duplicate-start 409s for queued, waiting, running and merged work. Current failure reasons and delivery limitations remain outside the selected historical report, so inspecting an older failure cannot make it the current blocker. The container/card and manual action selectors are retired; those diagnostics remain required.
