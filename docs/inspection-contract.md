# Issue inspection acceptance revision

Requirement 3 explicitly replaces title/description editing with read-only execution inspection and removes the Workbench tab and its administration page. Issue 12 owns this acceptance-contract revision. Issue 13 owns implementation and its new behavior checks. This revision changes no application, API, storage, controller, queue, review or integration source.

The obsolete editing and Workbench interactions cannot remain product requirements after the requested removal. Their underlying guarantees remain covered as follows. The revised checks run on the current application before implementation, using its existing identifier-based details view and real APIs. There are no compatibility branches, skipped tests or alternate verifier commands.

| Retired interaction | Replacement and retained guarantee |
| --- | --- |
| Rename through the edit form before restarting | A pinned API update is visible in read-only issue details, survives a complete owned server restart, and remains in SQLite/API results. |
| Edit title, description, status and priority through the title button | Creation remains a real UI operation; API updates retain all four fields after reload; identifier details show persisted title/description without editable inputs; confirmed deletion and cancellation/focus guarantees remain. |
| Edit/clear labels through the edit form | UI creation still normalizes and deduplicates labels; real API changes and clearing remain visible after reload, with combined label/status/search filtering, reset behavior and phone layout checks. Invalid UI drafts and full-restart label persistence remain unchanged. |
| Navigate to Workbench and open administration forms | Issue status navigation and identifier inspection retain keyboard focus and active-view semantics. Repository registration, requirement ownership validation, creation and duplicate-start refusal are exercised through the real APIs. |
| Workbench progress and blocker cards | Real API state and the existing shared progress/dependency/blocker functions prove deduplicated merges, manual Done limitations, whole-goal review versus planning review, latest-failure precedence, dependency waiting, historical blocker resolution, duplicate-start refusal and independently reviewed retry. |
| Workbench delivery-history selector | The issue's associated execution selector proves historical failed and merged reports, exact manifest download paths/bytes, browser downloads, loading, running, terminal absence and recoverable request failures. Long report evidence remains usable at 390px. |
| Workbench-based requirement/CLI walkthrough | Real API registration/start and actual conversation CLI intake still drive the serial queue through planning review, verified issue integration and whole-goal review. Original provenance, immutable submitted issues, merge commit and evidence are checked through API plus issue details. |
| Workbench-only server-rendered layout and manual-control expectations | Initial issue navigation and accessible controls are checked by rendering App. Detailed merge ownership, latest whole-goal outcomes, dependency waiting and blocker-supersession scenarios are retained against the existing shared state helpers. The requested page removal can therefore remove the retired component. Waiting maintenance is checked through its actual queued kind, absent run ID, empty execution history and refused ordinary claim. |
| Wrong-target PATCH through the retired edit dialog | PATCH still executes as a real browser fetch from the pinned loaded context through the same coordinated API replacement. It must return the original target identity and a 409/error body. POST and DELETE still use their real dialogs and visible errors. The unchanged parent test retains colliding IDs and byte-identical replacement records plus SQLite sequence assertions. |

The empty-workspace case now launches its own fresh server and database instead of relying on other test files leaving a shared database empty. It retains the original real empty collection, first-issue action, dismissal and focus assertions. A retained initial verification failure exposed that ordering dependency after the history checks moved earlier in discovery. No merged fixture rows are deleted to make it pass.

The three renamed required browser cases are explicit in `factory/verification-contract.json`. All other required cases remain named and mandatory. The five verification gates and report-inspection rules are unchanged. The contract regression proves that a report satisfying the new names is accepted and that omitting a required executed case is still rejected. Synthetic report fixtures in that unit check exercise the detector; they are never used as delivery evidence.

This prerequisite does not prove the new title interaction, absence of Workbench, inline text logs, richer errors or requirement audits in details. Issue 13 must add strict failing-then-passing checks for those behaviors, undergo independent acceptance coverage review, preserve these frozen checks, pass full candidate and integrated verification, and receive final independent integrated review. Requirement 3 still needs whole-goal verification and review after all merges.

Removing frontend administration does not remove backend APIs, conversation intake, queue records, execution evidence, dependencies or any historical data. No seeded data reset is part of this revision.
