# Browsing issues

Select a repository in the left primary toolbar, then inspect a requirement from its **Requirements** page. Its nested issue collection shows compact, read-only summaries with the title, identifier, status, priority and creation date. Titles occupy at most two lines. Each row shows up to two shortened labels and a count of additional labels. Open either the title or identifier to inspect the complete description, all labels, diagnostics, logs and audit evidence. Close the dialog with Escape or Close dialog to return focus to its opener.

Ownership is scoped before deriving search results, counts, labels, sorting and pages: both repository and requirement IDs must match. Combine title/description search, status and label filters. Label choices include only that owned collection. Newest, priority and title sorting apply to all matches before pagination. Each page contains up to 10 issues; the result range and Previous/Next buttons expose the full matching collection. No matches shows an empty range and offers Reset filters.

Changing search, status, label or sort starts at page 1. **Reset filters** returns to page 1 while retaining repository and requirement ownership. Selecting a different requirement or repository clears obsolete filters, pages and diagnostics. Background refresh keeps the current page when valid, moves to the last available page if results shrink, and retains previously loaded rows after a read failure. Empty results use page 1 so newly arriving matches are visible.

The repository-level **Unassigned** destination in the upper toolbar exposes only issues whose repository matches and whose requirement ID is null. Issues without repository ownership and dangling requirement references are excluded. This is existing standalone history, with no synthetic requirement or stored-data change.

Scroll within the bounded issue list to inspect rows while its heading and pagination remain outside the scrolling area. Search, filters, row openers and pagination support keyboard navigation at desktop and phone widths. Paging uses the loaded collection locally and sends no issue changes or execution requests.

Focus outlines appear after Tab or Shift+Tab navigation. Pointer input and leaving the window clear keyboard decoration without blurring the current element. Passive focus restoration does not enable outlines, and background refresh preserves the user's focus. Diagnostics initially focus the named dialog container without drawing a frame or selecting a control. Tab and Shift+Tab then reach the dialog controls and wrap within the modal; Escape and Close dialog restore the exact opener.
